# GLM 5.3 实施交接

对应方案：[简填优化调研与改造方案](OPTIMIZATION_RESEARCH_2026-10.md)。本文件只交接开发任务，没有执行模型开发、代码推送或正式发布。

## 1. 使用顺序

先合并或取用方案文档，再让 GLM 5.3 从公开仓库实施时的最新 `main` 创建开发分支。第一轮按 B0 → B1 → B2 → B3；第二轮 B4、B5 可分别推进，B6 在 B3 后做。只有第一轮完成还剩额度时再安排第二轮；不要求一次实现全部方案。

```text
B0 主线对齐与用例
 └─ B1 字段语义 ─ B2 AI 调度/缓存 ─ B3 写入与记录对应
                                     ├─ B5 人工收尾
                                     └─ B6 动态依赖
B0 ─ B4 简历实习解析（独立于填表主线）
B7 岗位与素材功能：另立需求
```

B0—B6 是后续开发任务，不是本方案 PR 的未完成代码。不要因为文档里有这些任务，就在方案 PR 中自动开始实现。

## 2. 通用开发提示词

将以下提示词与一个具体批次一起交给 GLM。每次只选择一个批次，避免长上下文一次改完多个系统。

```text
请在 QWE38qwe/resume-autofill-cn 实施本轮指定批次。
先读仓库 AGENTS.md（若有）、README、PRIVACY 和以下两份文档：
docs/OPTIMIZATION_RESEARCH_2026-10.md
docs/GLM_IMPLEMENTATION_HANDOFF.md

从实施时最新 main 新建 codex/ 前缀分支，检查已有实现及待合并改造。
优先复用公司名编辑、AI 候选选择、日期精度和受控输入相关成果，
不重复开发，不覆盖本地未提交修改，也不把它们顺带带入本轮 PR。
若依赖尚未进入 main，先报告依赖及整合方式；已有授权范围内可单独整合验证。

开始前用 3—6 条说明将改哪些文件，以及准确的验证命令和用途。
实现最小可审查改动，保持原生 JS/MV3、无构建步骤和现有架构。
建议函数名与数据形状只是设计示意，先查实际代码，不能当成现成 API。
不要全量拆分 content.js/manager.js，不新增 hash、冻结 contract、
baseline 或发布 gate，不删除已有安全措施，不加遥测或新外部请求。

字段映射不发送个人资料值；解析简历继续遵守已有用户授权范围。
不推断个人事实，不自动提交、保存或投递，附件继续显式确认。
自定义规则、个人资料和已有 aiRules 不能因缓存改造被删除。

给行为改动补真实生产逻辑测试，先跑最快的受影响检查，再跑对应浏览器夹具。
测试使用虚构资料和 mock AI，不消耗真实 API 额度，不上传真实简历。
失败要定位原因，不能改断言掩盖失败；未做的验收应明确列出。

完成后提交本批次的独立代码 PR 到公开仓库 main，并同步代码到 GitHub。
PR 写清问题、行为变化、测试命令与结果、已知限制和回退方式；不要直接合并。
不要提交密钥、邮箱授权码、真实个人资料、原始邮件、完整 HTML 或临时调试脚本。
```

若 GLM 工具没有 GitHub 推送权限，应交付已提交的本地分支、准确命令和失败原因，不得声称同步成功。密钥由用户通过环境变量或工具已有的认证流程提供，不能写入方案、代码或日志。

## 3. 分批实施卡

以下路径均为仓库已有入口；“拟新增”表示实施时才创建。已有模块能承载时优先复用，避免为清单数量强行增文件。

### B0：对齐主线与验证入口

- **读取**：`content.js`、`background.js`、`manager.js`、`popup.js`、现有 `tests/*-fixture.html`、`tests/submission-demo.test.cjs`、`scripts/privacy-check.sh`。
- **核对**：实施起点是否已有 `aiMatchOption`/`decideOption`、日期精度和公司名人工锁定；相关方案文档是否已经合并。当前研究 main 尚未包含本地审阅的全部成果。
- **交付**：E1/E2 的生产函数回归入口及后续受影响夹具运行说明；如需抽取纯函数，只抽本轮会修改的决策逻辑。
- **验收**：测试确实能暴露当前 E1/E2，后续对应修复才能转绿；现有夹具的已知失败单独记录，不能顺带大修。
- **提交策略**：不向 main 合入故意失败测试。可先给修复分支准备测试提交，再随 B1/B2 修复一并提交；缺少主线的旧功能单独 PR。

可复制任务尾句：

```text
本轮只做 B0。确认现有分支与 main 的实际差异，列出需复用的功能，
为 E1/E2 准备调用生产函数的回归用例和执行命令。
不要提前实现 B1—B7；不把失败测试单独合入 main。
```

### B1：字段证据与消歧

- **主要文件**：`content.js`；拟新增字段决策纯函数测试。若增加小型生产 helper，脚本加载和测试必须调用同一实现。
- **实现**：分离 label/ARIA/placeholder/autocomplete/附近文字；按人物、区块、类型判断；保留冲突候选，处理平分和英文词边界。保持基础字段和重复字段使用一致决策原则。
- **必测**：联系人电话与通用手机号占位符；本人/联系人姓名；学校/学院；学历/学位；三个城市用途；项目/工作描述；username/companyName；自定义别名冲突；弱泛化标签拒填。
- **边界**：`section-*` 仅分组；不按其字符串推断人物身份，不猜中文姓/名拆分。

```text
本轮只实现 B1，先写能复现 E1 的回归，再修证据来源和冲突决策。
不要只给 emergencyContactPhone 加特判，也不要只增加别名或换定义顺序。
保留现有控件适配和字段取值语义，完成后单独提交 PR。
```

### B2：本地优先、AI 缓存与陈旧响应

- **主要文件**：`content.js`、`background.js`、`popup.js`；必要时更新 `README.md`、`PRIVACY.md`；拟新增调度与缓存测试。
- **实现**：普通扫描不请求 AI；本地可确定项先填，未确定项才走已有接口；停止使用自动持久 `aiFieldMappings`，同次内存比较完整描述；结果检查候选白名单、目标、类型和会话有效性。
- **必测**：E2；全本地表单 0 次字段映射请求；混合表单仅请求不确定项；无模型/断网；重复 fieldId、非法 targetKey；页面重载、版本切换与迟到响应；超 120 字段的明确待处理反馈；iframe 与既有候选预算共享。
- **边界**：不新增 hash 替代截断键；不删除自定义规则；不扩大字段映射的资料发送范围。

```text
本轮只实现 B2，先验证 E2 碰撞，再调整 scan/fill 两个入口的调用顺序。
使用 mock 计数验证真实请求数量；不要用“缓存命中”字样代替测量。
复用已合入的候选 AI 隐私与预算规则，失败不影响本地填充。
```

### B3：占用与写入可靠性

- **主要文件**：`content.js`；现有受控输入、Hotjob、京东、B站、日期和附件夹具；拟新增记录对应/去重场景。
- **实现**：占用区分尝试/成功/保留；去重带区块和人物用途；未处理记录字段留在本记录；空块按顺序，有值块只做唯一对应；补齐绕过回读的路径。
- **必测**：第一处失败后同用途后备目标；确认邮箱；本人和联系人；同公司不同日期；已有记录顺序不同；原值保留；radio/自定义下拉点击后被重置；受控节点替换；附件和日期规范化结果。
- **边界**：不能让所有未 handled 的重复字段进入全页基础匹配；不能取消 readonly 后直接统计成功；不承诺完整撤销网站副作用。

```text
本轮只实现 B3，复用 fillPlainControl，重点覆盖工作布局和选项类的旁路。
成功必须由当前控件状态证明，部分成功要如实展示。
若记录对应和写后确认分别造成大 diff，可拆成 B3a/B3b 两个 PR。
```

### B4：PDF 与实习解析

- **主要文件**：`manager.js`；拟新增布局文本项、人工 PDF 和导入预览夹具；必要时更新使用说明。
- **实现**：版面顺序与经历分段分离、来源区间、AI 输出类型/日期/证据校验、截断提示；原文对照扩展现有预览。
- **必测**：单栏、双栏、跨栏标题、跨页、日期独行、公司名短横线、正文年份、同公司两段、科研干扰、空/无文字层文件、60000 字符边界、非字符串字段与虚构内容、取消预览不写入。
- **边界**：版本导入仍只处理实习；Markdown 导入独立；不新增 OCR、外部服务和自动多次上传。

```text
本轮只实现 B4，先用人工文本项复现布局问题，再用合成 PDF 验证生产导入。
禁止把全页简单按 X 排序，禁止为了识别更多内容覆盖个人/教育资料。
无法确认的解析结果留在可编辑预览，不自动保存。
```

### B5：待处理定位与站点纠正

- **主要文件**：`content.js`、`popup.js`、`popup.html`、`styles.css`；需要管理持久规则时再改 `manager.js`、`options.html`、`PRIVACY.md`、`docs/DATA_MIGRATION.md`。
- **实现**：原因与下一步、失效句柄重定位、本地资料搜索、明确手选后单字段填写；“本次”和“记住此站点”分开，站点记忆仅存映射描述与 targetKey。
- **必测**：跨 frame/重载定位；跨 origin/租户/区块不复用；规则禁用和资料变更；旧数据无新键；未确认不上传；敏感串不进入诊断；导入导出规则的兼容性。
- **边界**：不新增 Side Panel 权限；不自动学习所有用户输入；不把个人答案或整份资料放到网站可读取的 DOM/消息；不自动上传反馈。

```text
本轮只实现 B5，先让待处理项可定位、可选资料单次修正，
再增加显式的站点纠正记忆；必要时拆成 B5a/B5b。
复用现有自定义字段和 aiRules，避免新增第二套固定答案库。
```

### B6：动态依赖与局部重扫

- **主要文件**：`content.js`；现有重复经历夹具及拟新增级联/延迟事件夹具。
- **实现**：新增块、依赖选项的定向等待；父项变化使子项旧快照失效；明确折叠区扫描；版本切换和取消时清理旧观察。
- **必测**：延迟追加、超时后迟到、连续重绘、父项变更、导航取消、局部重扫保留手改值；同一区块“展开”和“新增/删除/提交”并存。
- **边界**：不全页常驻监听；不自动点下一步/保存/提交，不借扫描任意追加记录。

```text
本轮只实现 B6，先用可控事件模拟慢响应，再替换受影响路径的固定等待。
保留有上限的超时回退，验证超时后响应迟到不会导致重复追加。
页面下一步由用户操作，扩展只提示重新扫描。
```

## 4. 验证与 GitHub 交付

现有命令按实际改动选用，纯文档不要求跑无关运行时全量测试：

```powershell
node --check content.js
node --check background.js
node --check manager.js
node --check popup.js
git diff --check
```

修改解析脚本时补 `node --check scripts/md-resume-parse.js`。新增 `*.test.cjs` 后，使用 `node --test <本轮测试路径>`；该占位符须替换为真实已创建的文件，不能声称已有对应测试。独立模拟页已有 `node --test tests/submission-demo.test.cjs`，只有触及该页时才需要运行，不能拿它证明填表内核正确。

浏览器夹具按 README 用本地静态服务器打开，例如：

```powershell
python -m http.server 8877
```

对受影响夹具实际触发填写，读取断言/页面最终状态，保存虚构数据截图或文字结果。现有隐私扫描需 Bash：`bash scripts/privacy-check.sh`；运行条件缺失就明确报告并补等价静态审阅，不能声称通过。性能数字至少注明夹具、样本数、是否启用 mock AI 和测量口径。

每个代码 PR 只提交本批次文件。使用具名 `git add <文件>`，提交前检查暂存差异；不使用 `git add .` 混入临时脚本。通过 GitHub 工具或 CLI 创建到 main 的 PR，并返回可访问链接；无需等额度耗尽再同步，也不要直接合并或发布。

PR 交付清单：

- [ ] 关联本方案及批次编号，说明实际代码起点与已复用能力。
- [ ] 列出改动文件、用户可见变化、错误/跳过路径。
- [ ] 写明实际执行的检查与浏览器用例，未验证项单独列出。
- [ ] 公开 diff 不含个人资料、Key、邮箱凭据、原始简历和邮件。
- [ ] 如改权限/存储/发送范围，同步相应说明并保持已有安全限制。
- [ ] 代码已推送 GitHub，PR 目标为 main，未直接合并。

每批次完成后停下，由用户决定下一批次。若额度将到期，优先完成、验证并同步当前批次，不以“多开任务”代替完整交付。
