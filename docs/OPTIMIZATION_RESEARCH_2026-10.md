# 简填优化调研与改造方案

调研日期：2026-10-15。代码依据：公开仓库 [`main@5e2377c`](https://github.com/QWE38qwe/resume-autofill-cn/tree/5e2377c8cdfa60f4a30b243b37e7a6110481b246)。

本文提交调研、设计和验收要求，尚未实现其中的改造。GLM 5.3 开发入口见 [实施交接](GLM_IMPLEMENTATION_HANDOFF.md)。

## 1. 建议先做什么

优先减少错填、漏填和重复调用 AI，再增加便于人工收尾的功能。建议第一轮完成 B0—B3，第二轮做 B4—B6；B7 留作后续选题。各任务单独提交 PR，前一项验收后再继续有依赖的任务。

| 批次 | 优先级 | 交付 | 收益 | 相对工作量 |
| --- | --- | --- | --- | --- |
| B0 | P0 | 对齐主线、建立本次行为用例 | 避免覆盖已有改造，让后续结果可比较 | 小 |
| B1 | P0 | 保留字段证据来源，处理语义冲突 | 避免本人/联系人、学校/学院、工作/项目混填 | 中 |
| B2 | P0 | 本地优先调度、修正 AI 字段缓存复用 | 减少等待、错误缓存和无效请求 | 小至中 |
| B3 | P0 | 字段占用、重复记录对应和写后确认 | 降低“显示成功但页面没值”、第一处失败后其他处漏填 | 中至大 |
| B4 | P1 | PDF 阅读顺序与实习解析证据 | 减少双栏串行、多段实习合并、正文丢失 | 中至大 |
| B5 | P1 | 待处理字段定位、资料搜索、站点纠正记忆 | 把失败转成用户能完成的一步操作 | 中 |
| B6 | P1 | 动态字段重扫、级联控件定向等待 | 减少新出现的必填项漏填、父项切换后子项失效 | 中 |
| B7 | P2 | 岗位快照、岗位粒度记录、问答素材复用 | 增加求职流程价值 | 分项评估 |

工作量仅表示复杂度，不承诺开发耗时或免费额度可覆盖范围。GLM 在本轮作为开发工具使用；插件运行时不新增对 GLM 的依赖，不需要为实施方案提供 API Key。

## 3. 代码证据与实验

### E1：字段证据被拼接，平分时依赖定义顺序

[`labelOf()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/content.js#L393) 已收集 label、ARIA、placeholder、name、autocomplete、id 和附近文字。问题不是“没有读取这些属性”，而是把不同可靠性的线索合并为一个字符串。

[`aliasScore()` / `matchControl()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/content.js#L549) 保留最高分，基础字段没有候选间差距与冲突决策；自定义字段还直接加 4 分。

用该提交的真实 `FIELD_DEFS`、`normalizeText()`、`aliasScore()`、`bestAlias()` 运行合成输入，结果如下。此实验验证评分内核，不代表已在真实招聘网站复现完整 DOM 流程。

```text
合并后的字段文本：紧急联系人手机号 手机号码
phone                 96
emergencyContactPhone 96
emergencyContactName  88
当前仅使用 > 比较：先定义的 phone 胜出
```

这类标签与通用 placeholder 的冲突应由强标签及联系人区块决定；无法确定时应待处理。再加同义词不能从根上解决。

### E2：AI 字段缓存键会碰撞

[`aiMatchFields()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/background.js#L281) 用 `hostname + signature.length + signature.slice(0, 300)` 作为持久缓存键，最多保留 30 项。

运行生产代码中的签名和缓存键表达式：首字段 label 为 180 个 `x`、id 为 80 个 `f`，其他元数据相同；第二字段分别为“毕业院校”和“工作单位”。这两个字段长度符合当前元数据截断范围。

```text
完整签名不同：true
完整签名长度：449 / 449
当前缓存键相同：true
```

因此可能把第二个页面的 `field-1` 复用成第一个页面的字段映射。修复不需要新增 hash、缓存版本门禁或冻结 schema，见 B2。

### E3：AI 请求早于基础字段的本地决策

[`fillCurrentFrame()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/content.js#L3324) 先填重复经历，再对剩余全部 targets 调 `requestAiMappings()`，之后才进入 `fillBaseFields()`。因此配置 AI 时，容易先等模型再填本来能本地确定的基础字段。弹窗初始化的扫描也可参与 AI 匹配，改造应同时覆盖扫描和填写入口。

这是静态调用链结论，尚未测量实际延迟或 token 节省比例。

### E4：字段占用早于写入结果确认

[`fillBaseFields()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/content.js#L3163) 在写入前设置 `claimedSingleValueKeys`、`handled`。失败后同 key 的其他目标可能被跳过；全页单值去重也不能表达“邮箱/确认邮箱”等合法重复用途。

[`fillRecord()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/content.js#L2961) 末尾将整个记录块所有控件标为 used，可能使未匹配字段失去基础扫描机会。修复时必须保留记录区块边界，不能直接让基础字段接管所有未处理控件。

### E5：已有写后确认，但路径未完全统一

[`fillPlainControl()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/content.js#L1095) 已处理普通受控输入回读及替换节点重试。不能重做一套普通输入写入器。

其他路径仍有“点击后返回 filled”，或 `fillWorkByLayout()` 中 `forceNativeValue()` 后直接递增成功数的做法。改造应复用已有能力，统一这些旁路的最终结果判定。[React 官方输入文档](https://react.dev/reference/react-dom/components/input)也说明受控值由组件状态驱动；一次 DOM 赋值不能代表状态已经持久接受。

### E6：重复记录以数组和页面位置对应，等待使用固定时间

[`fillRepeatedSections()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/content.js#L3052) 按 `records[index]` 对 `blocks[index]` 填写；`ensureRecordBlocks()` 点击追加后固定等待 420ms。已有记录顺序不同、异步加载较慢、记录标题相似时，需要更明确的对应与停止条件。这是风险路径，尚未进行真实站点覆盖率统计。

### E7：PDF 处理依赖内容项顺序，解析需要更可追溯

[`extractPdfText()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/manager.js#L2415) 依次读取 `content.items`，主要按 Y 差与 `hasEOL` 换行，没有用 X 坐标处理双栏顺序。双栏问题需要合成 PDF 和真实脱敏样本验证，不能仅按 X 全页排序。

[`localInternships()` / `parseInternships()`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/manager.js#L2705) 已有断行修复、标题判断、多段拆分和预览；AI 导入取全文前 60000 字符，后续对 internships 做归一化。应加强原文区间、输出校验和截断提示，保留当前“版本解析只提取实习，不覆盖个人/教育”的语义。

### E8：填表记录按公司去重

[`popup.js`](https://github.com/QWE38qwe/resume-autofill-cn/blob/5e2377c8cdfa60f4a30b243b37e7a6110481b246/popup.js#L9) 的 `historyKey()` 主要使用公司名，弹窗初始化还会压缩历史。若以后做岗位跟踪，同公司多岗位可能丢失区分；填表动作本身也不能证明用户已提交。B7 需要独立设计，不能顺手把当前记录改成“已投递”。

## 4. 详细设计

### B0：主线对齐与验证准备

1. 开发从实施时的最新 main 开始，记录实际起点。先检查已有分支或待合并改造；本次本地审阅发现主线之外已有公司名编辑、AI 候选选择、日期精度相关实现。若已合入，直接复用；尚未合入时单独整合并验证，不能混入后续任务或重复生成。
2. 区分三层：字段映射回答“这个控件表示什么”；取值回答“该版本哪条资料”；候选选择回答“当前控件选哪一项”。保留现有候选白名单、敏感字段限制、日期规则、附件确认和不自动提交约束。
3. 用 E1、E2 建立真实生产函数回归，并补充 B1—B6 的失败用例。用 `node:test` 测纯决策；DOM 行为复用现有 HTML 夹具和扩展运行时 mock。
4. 先跑受影响夹具，再扩到同类组件。记录成功、错误写入、主动跳过、请求数与耗时。仅本地测试输出，不增加遥测、固定 baseline 文件或发布 gate。

### B1：保留证据来源，按字段语境决策

在现有匹配入口旁增加小型纯函数，逐步替换本次受影响逻辑；不整体拆分 `content.js`，不迁移技术栈。以下名称是设计示意，不是现有 API 或冻结接口。

```text
控件 → 收集有来源的证据 → 确定区块/记录/人物角色
     → 召回候选 → 检查冲突与控件类型 → 本地确定或待处理
```

证据分别保存：关联 label、ARIA 名称、明确字段标题、autocomplete tokens、name/id、placeholder、帮助文本、附近区块。共享同一段文本的多个属性不能算多次独立支持；`aria-describedby` 作为说明，不能与字段名等权。

关联标签可以参考 [W3C 表单标签说明](https://www.w3.org/WAI/tutorials/forms/labels/)。本项目需要保留多种语义证据，不声称实现完整的浏览器 accessible-name 计算。

决策要求：

- 明确关联的“紧急联系人手机号”及联系人区块优先于通用 placeholder“手机号码”；两条同等强度证据互相冲突时待处理。
- 弱附近文字只用于召回，不能单独把泛化的“名称”“时间”“描述”写成具体字段。
- `autocomplete` 按 token 解析，将 `email`、`tel`、`bday` 等转换成兼容的标准 key；结合人物和区块使用，不能盖过明显冲突的标签。
- `section-*` 只表示分组，不能从 `section-child` 等字符串猜人物关系；这与 [HTML 标准](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill)一致。联系人身份仍需标签或区块证明。
- 英文按词边界和已知属性词拆分，避免 `username`、`companyName` 仅凭 `name` 子串映射成本人姓名。无法可靠拆分 given/family name 时不猜中文姓名结构。
- 候选保留第一、第二名与证据；不能用定义顺序处理平分，不能让自定义字段统一加分后覆盖强标准标签。
- 单值、文件、日期、选项组使用类型约束；教育区内的 level/degree/type 和项目/工作 description 分别归属。

首轮沿用现有可解释评分作为召回依据，先修证据优先级和平分冲突。新数值阈值只有在具体用例证明需要时才调整，不宣称分数是概率。

验收：E1 选择联系人电话或明确待处理，绝不能填本人电话；学校/学院、学位/学历、户籍/现居/期望城市、本人/联系人姓名、项目/实习描述、中英混合标签均有正反用例。

### B2：先本地决策，再对不确定项请求 AI

1. 扫描默认只做本地识别并展示状态；需要 AI 时由用户触发填写或明确的重新匹配操作发起。扫描计数应说明是本地识别结果。
2. 为本次填写建立内存会话，保存目标句柄、所属 frame/区块、源版本和候选集合。先执行本地已确定项；仅将未确定项的最小元数据送入已有字段映射接口。
3. AI 响应只接受本次未处理目标和已有候选 key；重复 fieldId、类型错误、低置信、陈旧页面/版本响应不得直接写入。响应只是候选证据，仍要经过区块、类型和取值检查。
4. 停止读取和写入自动生成的持久 `aiFieldMappings`，改为当前填写会话内存复用。相同会话中使用完整、规范化且包含候选 key 集的描述作比较；不截前缀，不新增 hash。旧缓存可保留为未使用数据，不能误删用户自定义规则或资料。
5. 不将会话内 DOM 节点写入扩展存储，也不将个人资料值、完整简历、附件内容或整页 HTML 混入字段映射请求。注意父容器文本可能夹带已填值，采集阶段必须避免这种内容。
6. 请求失败、超时或无模型时保留本地已填结果，余项进入待处理。复用现有失败回退和预算；候选 AI 若已有每次 8 次限制，要让顶层和 iframe 共享同次预算，不能每个 frame 重新获得额度。
7. 保留现有 120 个字段/候选上限的限制语义；超过范围时明确展示未处理项，不以静默截断冒充全页完成。后续若需分批，另用大量字段夹具验证响应关联。

取舍：跨次填写可能多请求一次模型，换取不复用另一张表单映射。B1 的本地覆盖和同次内存复用抵消部分开销；实际请求量以测量为准。

验收：E2 两张表不能互相复用；全本地可确定表单产生 0 次字段映射请求；普通扫描不触发网络；混合表单只发送不确定项；断网仍完成本地字段；切换版本、frame 重载、删除目标后到达的旧响应不写入。

### B3：范围内占用、重复记录对应与最终回读

字段“已识别”“已尝试”“已成功”“原有内容保留”分别记录，不能写入前永久占用。失败可释放该目标的尝试状态，但仍保留其区块归属，禁止让本人资料落入联系人或重复经历。

- 用本次会话中的 frame、区块、人物角色、记录和字段语义限定去重；同一控件不重复写，明确的“邮箱/确认邮箱”可写相同来源值。
- 若存在多个同义目标，先比较可靠性再选择；失败后的后备目标也必须属于同一语义用途，不能随便换下一个 input。
- 记录块分别记录“属于该记录区块”和“该控件已成功处理”，替代把整个块所有控件一律标为 used 的做法。未识别项留在该记录的待处理列表，不交给无区块限制的基础字段填写。
- 空记录块继续使用用户选定顺序。有内容的记录块，只有学校/公司和日期等信息唯一对应时才重用；相同公司不同日期须区分。歧义时列出待核对项，不重排或删除网页原有记录。
- 复用 `fillPlainControl()`；为原生 select、radio、按钮组、自定义下拉、日期、附件和工作布局旁路统一补齐结果回读。对应值被框架重置、节点替换或校验拒绝时不能计成功。
- 对日期精度、选项语义使用各自规范化比较，不能用任意字符串包含代替相等。附件按当前选中文件和目标用途检查，不因文件不同名而随意重传。
- 不靠取消 readonly、写 value 属性、发送 Enter 后直接报成功。保留既有特殊适配的必要兼容，逐条以真实控件状态验证，不能为简化删掉原有安全限制。

重试只在目标仍属于当前会话且可唯一重定位时进行，沿用已有有限重试；始终失败则待处理，不循环强写。

验收：第一处电话写入失败不会吞掉同用途的有效目标；本人/联系人互不占用；确认邮箱正常；两段同公司不同日期正确对应；框架异步清空、重建节点和选项点击无效均不得报绿；补充填写保留用户原值。

### B4：让实习解析保留原文依据

1. PDF 提取先保留 page、X/Y、宽高及文字片段。行聚合考虑字体/高度差；双栏先判断栏区、跨栏标题和页眉页脚，再确定阅读顺序。不把全页所有片段按 X 或 Y 简单排序。
2. 将“布局恢复”和“经历分段”分开。实习区块、公司/职位标题、日期、正文条目分别保留来源区间；同公司不同日期不得自动合并，正文里的年份不能单独触发新经历。
3. 本地解析和 AI 归一化复用同一套字段类型、长度、日期与原文依据检查。原文无明确日期时保留空值或原文，不编月份；非实习内容不能因含公司名就纳入。
4. AI 返回非对象、字段为数组/对象、空经历、日期倒置或内容无原文依据时给出可操作反馈。证据不足的字段只供预览修正，不自动写入资料库。
5. 原文对照、缺项提醒和拆分/合并操作只扩展现有解析预览；未点击创建版本前不改资料库。原文和坐标证据默认只在当前导入会话内存中使用，不新增持久副本。
6. 保留当前 PDF/TXT 版本导入只处理实习的语义，Markdown 标签导入继续使用 `scripts/md-resume-parse.js`。不借本次改造覆盖个人或教育资料。
7. 超出 60000 字符时不能静默丢尾：至少提示截断并停止自动认定解析完整；优先本地划定实习段后送入现有已授权的解析流程。调用量增加或上传范围改变时需明确展示，不能在此任务悄悄分段发多次请求。
8. 无文字层 PDF 明确提示改用文本或有文字层文件；OCR、模型视觉解析另立需求，不新增外部调用。

验收：单栏、双栏、跨栏标题、跨页经历、日期独占一行、中文年月、至今、标题含短横线、正文含年份/百分比、同公司两段、仅科研、无实习标题、空文档和恶意 AI 输出。使用虚构公司及人工构造的 PDF 文本项/PDF 文件，分别验证布局和生产导入入口。

### B5：待处理字段能定位、能修正、能复用

先复用弹窗结果区和现有管理页，不为此增加 Side Panel 权限或新后台服务。

- 每个待处理项显示网页标签、所属区块、原因和下一步：资料缺失去补资料；语义不明选标准字段；候选不确定让用户在当前网页选择；只读/不支持控件提供复制。
- 点击定位后滚动并短暂高亮目标；目标失效时只在原 frame 和区块重新定位一次，无法唯一找到就提示重扫。
- 资料搜索由扩展本地界面展示结果，不在页面可读 DOM、诊断导出或页面消息中放整份资料；用户明确选择后才向对应控件写一个值。附件继续要求既有显式确认。
- “本次使用”只作用于内存。用户明确点击“记住此站点”才保存映射，保存标准 targetKey 与最小字段描述，不保存个人答案、候选快照、整页文本或完整 URL 查询参数。
- 站点记忆至少区分实际 frame 的 origin、表单区块、标签、控件类型与用途；不将所有北森租户或同 hostname 下的所有表单视为同一结构。路由仅保留必要的非个人模板片段；无法安全概括时只做本次纠正。
- 规则只在唯一匹配且类型、区块兼容时生效；同名字段有多个或强标签变化时回到待处理。支持在管理页查看、禁用、删除和清空站点纠正；保留已有 customFields 和 aiRules。
- 设置的 JSON 迁移范围发生变化时同步 `docs/DATA_MIGRATION.md` 与隐私说明；自动 AI 缓存仍不进入这种人工规则。

诊断导出为本地文件，导出前预览最小字段元数据。排除资料值、用户答案、邮箱/电话、API 配置、DOM/完整 HTML、完整 URL、附件及原始模型响应；自由文本标签也可能含个人信息，必须脱敏且不能只依靠键名过滤。不自动上传或创建 Issue。

可选的“只填这一区块”先选择已识别区块，不做跨 iframe 任意像素框选；使用相同匹配与写入逻辑。完整撤销暂缓，文件上传、已追加记录和网站副作用无法靠恢复 value 全面还原。

验收：待处理项可定位；跨 frame/重载后的过期句柄不会定位到别处；规则不跨租户/联系人区块误用；资料修改后取新值；禁用规则立即生效；导出文件不含人工放入的敏感测试串；关闭弹窗不造成整表重填。

### B6：对动态表单按依赖等待

在用户发起的同次填写中，对刚操作的组件或区块短时观察变化，结合现有定时回退；避免全页常驻监听和反复全量扫描。

- 点击“新增经历”后等待目标区块数量增加或明确错误，超时就停止并提示；重复点击前先重新检查是否已有新增块，防止慢响应导致多加一条。
- 省→市→区、学校→专业等有明确依赖时，父项成功后重新读取子项可用状态与候选。父项变化后旧候选结果立即失效；没有明确依赖就不推测关系。
- 自动展开只限明确折叠的表单区块，排除添加、删除、同意、保存、下一步、提交等按钮。新增记录继续沿现有受限逻辑，不能混在“深度扫描”里任意点击。
- 新出现字段加入当前区块待处理；覆盖模式也不能因为局部重扫再次覆盖用户刚修改的字段。
- 用户主动进入下一步后提示重新扫描，不自动跨页、自动保存或自动提交。导航、版本切换、取消时结束旧观察和请求回写。

验收：慢追加、父项选后子项延迟出现、父项切换清空子项、反复 DOM 重绘、折叠区与新增按钮并存、用户中途修改字段、取消操作、跨页返回。用可控事件模拟不同响应顺序，避免只靠固定 sleep 的脆弱断言。
